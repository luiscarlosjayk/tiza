# Tiza v0.1.1

**Draw on top of code in your terminal to explain, debug and teach.**

This release adds the WebP export and a docs website. It also fixes the bugs that we found after v0.1.0. Most of them are in the local API, in supervised mode and in the theme files.

![Tiza explains Rust ownership step by step](https://raw.githubusercontent.com/luiscarlosjayk/tiza/v0.1.1/docs/img/ownership.webp)

Report a bug that you can reproduce with the [bug report form](https://github.com/luiscarlosjayk/tiza/issues/new/choose). Put feedback, ideas and terminal reports in [Discussions](https://github.com/luiscarlosjayk/tiza/discussions).

## What is new

- **WebP export.** `tiza render demo.tiza --out demo.webp` writes a lossless animation of all the steps, with the frames and the times of the GIF. With `--step N`, it writes a still of one step, with the pixels of the PNG. `:export`, `--all-steps` and the MCP tool `export_image` also write WebP. A WebP is usually smaller than the PNG or the GIF of the same steps.
- **A docs website.** The docs of the latest release are at [tiza.luisk.dev](https://tiza.luisk.dev). The site has a search box, a dark and a light theme, and a link on each heading.
- **A page for each group of commands.** Each `:` command has its own section, with its options, their values and their defaults. Real Tiza frames show what the annotation commands draw.
- **Prompts for your agent.** The agent pages have prompts to copy. One prompt sets up the Tiza MCP server. The others show what to ask an agent.
- **Codex.** The setup page tells how to add the Tiza MCP server to Codex: `codex mcp add tiza -- tiza mcp`.

## Fixes

- In supervised mode, an agent cannot turn supervised mode off with no review now. A request for a method that does not exist gets its error at once.
- The socket method `scene.clear` refuses parameters that it cannot read. Before, such a request deleted every annotation.
- Tiza does not remove a file at the socket path. It changes permissions only of its own runtime folder.
- In the config file and in a theme file, a wrong value leaves out only that token. Before, Tiza ignored the whole file.
- `tiza FILE:A-B` opens the document of that range from an earlier session. Before, autosave wrote over it.
- The MCP tools end their own refusals with `(invalid_argument)`, so an agent can tell them apart.
- An image export of a very long document stops with a clear message before it uses much memory. Before, Tiza used gigabytes of memory and then failed.

## Install

On macOS, and on Linux x86_64 with glibc 2.35 or later, run this command:

```sh
curl -fsSL https://raw.githubusercontent.com/luiscarlosjayk/tiza/main/install.sh | sh
```

The script checks the SHA-256 checksum of the download. Then it puts `tiza` in `~/.local/bin`. To update from v0.1.0, run the same command.

To install an archive yourself, use the file for your system:

| System | File |
|---|---|
| macOS, Apple Silicon | `tiza-v0.1.1-aarch64-apple-darwin.tar.gz` |
| macOS, Intel | `tiza-v0.1.1-x86_64-apple-darwin.tar.gz` |
| Linux x86_64 (glibc 2.35 or later: Ubuntu 22.04, Debian 12, Fedora 36 or later) | `tiza-v0.1.1-x86_64-unknown-linux-gnu.tar.gz` |

1. Download the file for your system and its `.sha256` file.
2. Check the file: `shasum -a 256 -c tiza-v0.1.1-<target>.tar.gz.sha256`. On Linux, you can use `sha256sum -c`.
3. Extract the file: `tar -xzf tiza-v0.1.1-<target>.tar.gz`
4. Make a folder in your PATH if you do not have one: `mkdir -p ~/.local/bin`
5. Copy `tiza` to that folder: `cp tiza-v0.1.1-<target>/tiza ~/.local/bin/`

**macOS:** The binaries do not have an Apple Developer ID signature. If you download the file with a web browser, macOS stops Tiza the first time and shows *"tiza" Not Opened*. To fix this, run this command one time: `xattr -d com.apple.quarantine ~/.local/bin/tiza`. A download with `curl` or with the install script does not have this problem.

**From source** (Rust 1.88 or later): run `cargo install tiza`. The `tiza` binary now contains libwebp, a C library, so `cargo install` also needs a C compiler. On macOS, install the Xcode Command Line Tools. On Debian and Ubuntu, install the `build-essential` package.

Tiza does not support Windows in version 0.x.

## Known limits

- We tested Tiza on macOS in the Zed terminal and in Herdr. Other terminals with 24-bit color and box-drawing characters should work. We did not test tmux and other terminals ([Terminal support](https://tiza.luisk.dev/reference/terminals/)).
- Use `find` to target a code change in a step, not a line number. If you edit the file while Tiza is closed, a change by line number applies to the lines that are at that number now.
