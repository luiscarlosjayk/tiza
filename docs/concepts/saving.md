# Saving

This page tells when Tiza writes the `.tiza` file, and what it writes when you quit.

**Saving** — every change is written to the `.tiza` sidecar as it happens (an atomic replace next to the source). Three things turn that off: `tiza FILE --no-save` (annotate an example or a demo without touching the file on disk: the bar shows `no-save`, then `unsaved (:saveas PATH · :q! discards)` once something changed, because `:w` would write over the file you opened; after `:saveas PATH`, every change saves to that new file), `:autosave off` live (the bar shows `autosave off`; `:autosave on` resumes and writes what is pending; `:autosave` alone shows the state, and `status` carries `autosave`), and a `scene put` of a document from another source, or with code that differs from the file it reads (the agent's document is shown, but the file that was open is never overwritten by it; the message says so). After a `scene get` → `scene put` of the open document, a sidecar that reads its code from a file still does (nothing gets embedded), and a put that changes nothing writes nothing. With autosave off, `:w` saves to the open file on purpose, `:saveas PATH` (`:sav`) saves elsewhere and keeps saving there (the message says `saved as PATH (autosave on)` or `(autosave off)`), and `:q` refuses while there are unsaved changes (`:q!` quits without saving). A relative path starts at the folder where you started Tiza, and `~` at its start is your home folder. Tiza creates the folders that are missing, and the message shows the full path. As in Vim, `:w PATH` writes a copy and the open file stays the one saved to, `:wq PATH` writes the copy and quits, and none of them overwrites an existing file without `!` (`:w! PATH`, `:sav! PATH`); the copy, or the file `:saveas` moves to, names its code, its linked files and `follows` from its own folder (`../main.rs`, or an absolute path when the two folders share only the root), so it opens from anywhere. A sidecar that cannot be written (a read-only file or folder — the atomic replace honours the file's read-only bit instead of walking over it) is the same state as `:autosave off`, one rule for all four cases: the first failed autosave says `read-only: could not save FILE — :saveas PATH to save elsewhere` once, then the message line is yours again (each command's own confirmation shows) and the bar keeps `read-only • unsaved (:w)` until a save works; `:q` refuses while there are unsaved changes (`unsaved (read-only): :q! quits without saving, :saveas PATH saves elsewhere`); if the file becomes writable again, the next autosave succeeds, says `saved to FILE` once and the indicator goes away. `render`, `scene get`, the exports and `--smoke` never write. **No way out writes anything the chosen mode would not have written already**: with autosave on every change is on disk the moment it is made, so quitting writes nothing more, and what could not be saved (a read-only file that became writable again) is retried once on the way out with Ctrl-C — never with `:q!`; with autosave off (or a read-only file) `:q!` and Ctrl-C quit without saving and print on stderr what was not saved (`tiza: quit without saving main.rs.tiza: 1 change not saved (note a1)`). `:q` refuses while changes are unsaved and `:wq` saves first. A terminal that goes away under Tiza (a pane or a tab closed, an SSH session dropped) quits it as Ctrl-C does; what it would have printed goes to `panics.log` in Tiza's runtime directory (`$XDG_RUNTIME_DIR/tiza/`, else `$TMPDIR/tiza/` or `/tmp/tiza/`), since there is no terminal left to print it on.
