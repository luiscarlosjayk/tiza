# Follow the editor

Use follow mode to edit the code in your editor while Tiza shows it.

**Follow mode** (`--follow` or `:follow on`) watches the source file's folder (Zed saves with a temp file + rename) and reloads the code about 120 ms after the last write, so you can edit in the editor while the TUI shows the result. Annotations are re-anchored by the text they point at, like a paste: a line diff matches the two versions in order (so a note on the second `}` stays on the second `}`), then the same occurrence of the span inside the line; a block moved elsewhere is followed when its line is unique and within 50 lines (a callout on it travels with it), a box, callout or spotlight whose edge line you edited or moved away keeps its height from the edge that stayed (it never stretches), a line you rewrote in place keeps its note and the spans whose text is still there (also when several adjacent lines are rewritten together, like a parameter renamed on the signature and on the line that uses it: the lines pair up one to one), a formatter that splits or joins a line (rustfmt) carries the span to the line that now holds its text, and the ones whose text is gone are dropped with a message — never moved to another copy — and `u` undoes the whole reload. A reload that changes no annotation leaves no undo step, so after an editor undo one `u` brings the dropped annotations back; the message after `u` names what it undid (`undone: reload #54`, `undone: note a3`, `undone: 3 annotations cleared`). The status line shows `⟳ following · last HH:MM:SSZ`; a removed file shows `waiting` until it comes back, an empty intermediate write is skipped, and embedded documents have nothing to follow (`:link path` first). A paste while following turns follow off too and says so (`follow off: the code is pasted, not main.rs; :follow on reloads main.rs`): the pasted code is yours, so a save in the editor no longer replaces it; `:follow on` loads the file over it as one reload `u` undoes (a paste of exactly what the file holds keeps following; with follow off it keeps the `.tiza` referencing the file); `u` back to the file says `follow is off: :follow on reloads main.rs`. An undo or a redo that brings back code the file no longer holds (one from before a reload, or from before a save in the editor) turns follow off the same way (`follow off: the code on screen is not main.rs; :follow on reloads main.rs`) and the `.tiza` keeps that code embedded, as after a paste, until `:follow on` reloads the file. The `.tiza` also names the file the code replaced (`"follows": {"file": "main.rs"}`), so `:follow on` and `--follow` still reload it after you quit and open the document again; `:embed`, `:link` and a reload back to the file clear it. `:link` or `:ref` at step 0 to a file whose code is not the one on screen (pasted, embedded, or another file's) loads that file's code the same way, so the screen always shows what the saved `.tiza` will; while following, follow moves to that file (a save of the old one no longer reloads anything), and `u` moves it back. A file a `code.link` already shows is refused (its annotations belong to that view), and `:link` with no path on a document that already references its file changes nothing. A save in the editor while moves are applied (step 1 or later) waits for step 0 (`main.rs changed on disk but moves are applied at step 2: go back to step 0 to reload`); meanwhile the `.tiza` keeps the code on screen embedded, so quitting there leaves a file that opens as it was shown, and back at step 0 the change is reloaded at once, as one reload `u` undoes (a file saved back as it was is no reload). `--follow` or `:follow on` at such a step (a `.tiza` opens at its saved `step`, 1 when it names none) turns follow on in that wait: `following main.rs (waiting: moves applied at step 1; loads at step 0)`. `:embed` while following turns follow off and says so: the code is frozen inside the `.tiza`, so later saves in the editor no longer reach the screen until `:link` and `:follow on`. Agents get the same through `follow.set` / `follow.status` and the MCP tool `set_follow`.
