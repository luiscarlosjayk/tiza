## [Unreleased]

### Changed
- The native GIF is drawn at `--scale 2` by default, like the PNG (t-121, Luis's decision on the t-120 review: at 1 long italic notes are soft on a retina screen); `export_image` with a `.gif` path too. MP4/WebM stay at 1. The ownership example: 1024×825, 171 kB → 2048×1650, 395 kB (under the 1 MB budget); `--scale 1` keeps the old output.
- README images refreshed with the current renderer (t-121): `docs/img/ownership.gif` (native GIF, 2202×1650, 396 kB — it was 960×773, stitched with Pillow on 2026-10-16), `docs/img/ownership-step7.png` (2202×1650, 217 kB) and the text block under the GIF, which still showed the old junction crossings; new hero image at the top, `docs/img/hero.png` (1200×630 at device scale 2, 681 kB), three real `--step 1/4/7` exports in an HTML frame (`docs/img/src/hero.html`, the title in Libron from `docs/brand/fonts/`). All regenerated by the new `scripts/readme-images.sh` (Tiza only; headless Chrome/Chromium for the hero, skipped if absent; deterministic). AGENTS.md: a visual change to the renderer re-runs it in the same commit.
- Release profile with fat LTO (t-133): `lto = "fat"` (was `"thin"`), still `codegen-units = 1`, `strip = true` and the default `panic = "unwind"` — `panic = "abort"` was considered and discarded, because a panic in a socket connection or an MCP call must fail that request only and never close the presenter's TUI. Linux x86_64: binary 14,001,752 → 13,158,152 bytes (−6.0 %), release tar.gz 6,513,078 → 6,321,068 (−2.9 %); macOS arm64 (measured by Luis before t-134): 12,292,992 → 11,374,320. Every benchmark scenario within noise; on the 2-CPU agent machine a cold release build takes 185 s instead of 154 s (+20 %) and a cold `cargo install --path crates/tiza-cli` 188 s instead of 154 s (+22 %).
- The SVG embeds only the font faces it draws (t-130): JetBrains Mono Regular always, Bold / Italic / Bold Italic only when a run with that style has text, and the *Tiza Symbols* fallback only when a character is missing from the run's JetBrains Mono face and the symbols font has it (coverage read from each face's `cmap` with `skrifa`, already in the tree through usvg). The drawing and the PNG/GIF bytes are unchanged and the SVG renders the same in a browser (Chromium screenshots compared pixel by pixel); only unused `@font-face` blocks go. Step 7 of `examples/ownership.rs.tiza`: 1,677,197 → 1,303,959 bytes (no bold italic); a document with no bold, italic or symbols: 1,658,895 → 378,801. The faces are still embedded whole (not subset to the glyphs used); `--no-embed-fonts` is unchanged.
- Exports set notes, labels and legends in the monospace by default (t-068 review: at 100 % the monospace reads better — more air between letters, even stroke — while the serif is narrow and its italics clump); the brand serif was opt-in with `tiza render --brand-font` / `export_image {brand_font: true}` (with 0.035 em of letter-spacing) until t-134 removed it from the binary (see Removed). `--mono-labels` became a hidden no-op. With the thinner monospace the dark theme's red (`drop` marks, `red`) fell to 4.46:1 after YouTube-like compression, so it is a touch lighter (`#FF4A66`, was `#FF3D5A`; 4.84:1 after compression, the t-072 gate). The unused `crates/tiza-export/fonts/` directory (an older JetBrains Mono and the DejaVu symbols file) is gone; its provenance README now lives next to the fonts that ship, in `crates/tiza-export/assets/fonts/`.
- **Renamed to Tiza** (t-108, [ADR 0008](docs/adr/0008-renombre-a-tiza.md)). Crate and binary `tiza` (libraries `tiza-core`, `tiza-tui`, `tiza-mcp`, `tiza-export`), `TIZA_SOCKET` / `TIZA_SESSION` (sockets under `tiza/`), sidecar `.tiza`, MCP server `tiza` with `tiza://` resources, fonts *Tiza Serif* (since removed from the binary, t-134) / *Tiza Symbols*, schemas `schema/tiza.schema.json` and `schema/api.schema.json`, wordmark `╭─ Tiza ─▶`. Old `.codedraw` files are not read (rename them). The v0.0.1 prerelease published as CodeDraw is withdrawn and re-tagged after this change; entries below this line still say `codedraw` where they were written before the rename. MCP clients registered as `codedraw` must be re-added as `tiza` and reconnected (`/mcp`).
- Render budget (t-054): a frame with 2,000 lines and 200 annotations went from ~220 ms to ~7 ms in release. Syntax highlighting is memoized (`highlight::highlight_cached`, last four results), the status bar reuses the frame's layout instead of computing a second one (`App::viewport_warnings_for`), and canvas cells store their grapheme inline (`canvas::Sym`, no `String` per cell). `qa/tests/t-054.rs` asserts the budget (16 ms release / 250 ms debug).
- All user-facing text (TUI, CLI, MCP, docs, examples) is now in English. Commands, JSON fields and the Spanish color aliases (`azul`, `verde`…) are unchanged; `:theme` keeps accepting `oscuro`/`claro`.

### Added
- README section «Terminal support» (t-034): verified on macOS in Zed's integrated terminal and in Herdr; any truecolor terminal with Unicode box drawing should work, the rest are untested. It lists what Tiza asks of the terminal as the code does it today (24-bit colour with no 256-colour fallback and `--theme terminal` as the way out, bracketed paste, mouse only with `--mouse`, the OSC 11/10 query of t-119 with its 100 ms fallback, no kitty keyboard protocol), the known caveats (Terminal.app before macOS 26, tmux — the query is not wrapped for passthrough, so `allow-passthrough` does not help — and Zed's `line_height`) and what to include in a terminal report. `qa/tests/t-034.rs` checks the section is there and that the code still does what it says.
- Size and speed budgets (t-133): `scripts/size-check.sh` builds the release binary, packs it as the Release workflow does and fails when the binary is over 16 MB, the tar.gz over 8 MB, or either grew more than 10 % over this target's baseline in `qa/budgets.json` (moving the baseline takes `--update --reason "…"` in the same commit; a hand edit that keeps the old reason is refused). `scripts/bench.sh` times `--version`, `render` of step 7 to .txt and .png, a generated 2,000-line Rust file and 3,000-line TypeScript file, the native GIF, the TUI's first frame on a pty and the t-054 frame median (one warm-up, median of 7), writes `qa/bench/latest.json` and warns — never fails — on any scenario more than 20 % slower than `qa/bench/baseline.json`; `--install` adds a cold `cargo install --path crates/tiza-cli` time, kept as information. First baselines: Linux x86_64 from this commit, macOS arm64 from the first run on Luis's Mac (452c576, fat LTO: binary 11,209,360 bytes, tar.gz 5,745,699; cold `cargo install` 64.7 s, 36 s with thin LTO); where the bytes go is in `qa/README.md` (Size breakdown). AGENTS.md asks for both before pushing a dependency or an embedded asset.
- Presentation mode shows the command line (t-107): pressing `:` while presenting draws the `:` line on the last row — over the padding or the last code line, the same text, completions and cursor as on the status bar — and Enter or Esc hides it; the command's result (confirmation or error) stays there for 2 s (`PRESENT_MESSAGE_TTL`) or until the next key, so a typo like `:foo` no longer fails in silence. Nothing else of the status bar appears; with the line hidden the frame is unchanged (snapshot in `qa/tests/t-107.rs`), and `render`, `--out` exports and the `.tape` do not draw the TUI frame at all.
- Moves between files (t-105, [ADR 0007](docs/adr/0007-moves-y-pasos-con-nombre.md) §3f rewritten): `code.link {file, lines?}` shows another file from its step on, and each file is a view with **its own annotations** — an annotation carries an optional `file` (absent = the document's own file), filled in from the file shown at its step when added without one; lines are real file line numbers; `lines` is only a window (a note outside it is kept, not drawn; the same file with another window is the same view); linking the main file again brings its annotations back untouched, nothing goes `(unanchored)` because of a link. `:link path[:A-B]` at a step ≥ 1 records the move (`:ref`, or `:link` at step 0, is the one-shot file reference); `:list`/`scene.list` end an annotation of a linked file with `(file)`; the bar shows `↪ file:A-B`; `code.get`, `status` and `move.list` report the view (`file`, `view`, `first_line`, `last_line`); a `code.patch` edits the file shown at its step; `:embed` and `scene.get` store every linked file under `views` so the demo stays one portable `.tiza`; a link to a file that cannot be read fails to load naming the move and the path. With it, `cursor {line, col?}`, `select {from, to}` (each end a `find` matching exactly once or `line`/`col`; drawn in the TUI, `render --step N` and every export) and `wait {ms}` (the TUI, the GIF and the `.tape` pause; a `.cast` holds the frame; a still render ignores it). Socket `move.add` and MCP `add_move` (`action`) accept the four; `examples/stack-and-queue.tiza` links a stack and a queue back and forth.
- Themes (t-119): a document that names no theme **follows the terminal** — OSC 11/10 at start (100 ms, silent dark fallback), light or dark by luminance, `dark·auto`/`light·auto` on the bar, re-asked on every resize (`kill -WINCH` by hand; mode 2031 is not enabled because the input library would read the report as keys); `t`, `:theme NAME`, `--theme` or a named theme fix it, `:theme auto` / `--theme auto` follow again and a following document is saved without a theme. **`:theme terminal`** / `--theme terminal` draws with the host's own palette (default colours, roles on the 16 ANSI colours, syntax on bat's `ansi` theme); exports fall back to dark/light with a notice. **Per-token overrides**: `[theme]` in `~/.config/tiza/config.toml` (`$TIZA_CONFIG`, `$XDG_CONFIG_HOME`) and `theme_overrides` in the document — every role and the named palette, as hex / `rgb()` / ANSI names / `reset`, with `[theme.dark]` / `[theme.light]` subtables; built-in → config → document → `:theme`; faint text is pushed to 4.5:1 and reported; `--theme-file PATH` / `:theme file PATH` load a file into the document (undoable), `render --theme-file` for one export. **Catppuccin Mocha** ships as the first and only override example (`examples/themes/catppuccin-mocha.toml`, public palette values, passes the legibility gate at 5.8:1). `set_theme` over MCP accepts the new names; `status.theme` unchanged. New crates: `toml` (core) and `rustix` as a direct dependency (tui).
- `:margin N` (t-113): caps the right margin at N cells (12-200; `:margin auto` restores the dynamic width, `:margin` reports) so long notes, labels and legends wrap earlier on a wide terminal instead of sitting on one long row; the frame ends at the cap, so a capped PNG has no blank band on the right and the code column is unchanged. Saved in the document (`"margin": N`), honoured by every export and by the agents' renders; `render --margin-cols N` overrides it once; `status.margin`, `scene.patch {margin: N | null}`; `u` undoes it. A cap wider than the dynamic margin changes nothing; a cap narrower than a mark's glyph + legend wraps the legend and keeps the glyph.
- `:numbers on|off` (t-112): hides the line-number gutter in the TUI — code, lanes and boxes shift left — and saves it in the document (`"numbers": false`; absent = on, so old files are unchanged), so `render`, `.cast`/`.gif`, `render.text`, `export_image` and the next session match. `render --no-numbers` still forces it off for one export and the new `--numbers` forces it on. `status.numbers` and `scene.patch {numbers}` for agents; `u` undoes the toggle. A `FILE:A-B` range keeps its real line numbers underneath (`L16` on the bar, text anchors unchanged).
- Narrow mode (t-116): with labels under the lines (< ~100 columns) an arrow's label is attached to its arrowhead — on the target line right after the code when it fits inside the code column (`fn takes(s: String) {  ─▶ move`, the glyph in the arrow's stroke and colour), otherwise on the row below behind that glyph instead of the bare `·`; several arrows into one line follow each other. Marks, notes and same-line arrows are unchanged, so is wide mode. A label inside a box range never touches the border.
- Native GIF export (t-120): `tiza render FILE --out demo.gif` (and `--format gif`) writes an animated GIF from Tiza's own frames — one per step from 0 (`--skip-zero`), `--interval` seconds each, the last one twice as long, the typed frames of `code.patch` moves at their `speed_ms` (rounded up to the format's 20 ms floor), `--loop N` (0 = forever), `--scale` 2 by default (1 until t-121), one palette per animation (frequent colours exact, blends median-cut, no dithering), frames after the first stored as the changed rectangle; the ownership example is ~395 kB (~170 kB with `--scale 1`). Every frame shares the take's geometry (t-111) and the masks (t-117); the live instance is recorded with `tiza render --out demo.gif` (no FILE) and over MCP with `export_image {path: "x.gif", interval, skip_zero}` (reply `format: gif`, `frames`, `steps`). `--out demo.mp4` / `.webm` muxes the same frames with the `ffmpeg` on PATH (or `$TIZA_FFMPEG`) through a printed command (30 fps, even dimensions, yuv420p / VP9), never bundled; without it: exit 2, install hints, and the reminder that `.gif`/`.cast` need nothing. Writes are temp + rename, so an interrupted render leaves nothing behind. `.cast` and `.tape` are unchanged; the README's recording section now goes GIF → MP4 → cast → tape. New crate `gif` (+ `weezl`) in `tiza-export` only; `tiza_core::anim::frames` and `moves::typing_plan` (the TUI's typing animation now runs on the same plan).
- Stable geometry across steps (t-111): presentation mode and every export (`render --step N`, `.cast`, `.tape`, `render.text`, `export_image`) size the arrow lanes, the box band, the code column and the margin once for the maximum over all steps (`layout::stable_geometry`, moves and masks included), and each multi-line arrow keeps its lane for the whole take — the code no longer slides sideways between steps and labels keep their margin. Authoring stays dynamic; `:layout stable|dynamic` rehearses with the take's geometry (`⊞ stable` on the bar). The presentation snapshot of t-053 at step 3 now shows the step-7 geometry.
- Redaction (t-117): a `redact` annotation masks a span of code on every surface at once — the TUI in normal and presentation mode, every export, `.cast`/`.tape`, `render.text`, `code.get`, `scene.get` and the MCP resources — with eight `•` plus the last `keep` characters, never the real length. `:redact L`, `:redact L:ANCHOR [keep=N]` (what follows the anchor; anchoring by the secret itself is refused), `:redact L@S..E`, select + `r`; socket `annotation.add {type: "redact"}`; MCP tool `redact`. Only the columns are stored: the `.tiza` written by `:w` or `:embed` never holds the text under a mask, and the file on disk is untouched. Masks are active from step 0 whatever the annotation's step (`redact_from_step` opts out); `:redact off|on` for the author's own screen with `◆ redacted` / `◆ UNMASKED` on the bar; a redact a reload or a paste cannot re-anchor is dropped with a loud notice. `:redact auto [--dry]` (opt-in, never automatic) turns the built-in patterns — JWTs, Bearer/Basic tokens, password/secret/token/api_key values, URL credentials, AWS/GitHub/Stripe/Slack/Google key prefixes, e-mail addresses — into ordinary redact annotations the presenter reviews. A text search (`find` in an annotation or a move) never matches under a mask, so an agent cannot probe a secret by substring. `regex` becomes a direct dependency of `tiza-core` (it was already in the tree through syntect).
- Network policy (t-118, [ADR 0009](docs/adr/0009-politica-de-red.md)): the `tiza` binary has no network dependencies and never opens a connection; anything that talks to the internet will live in a separate `tiza-net` crate and binary, run only on explicit command, print what it sends first, never include code or annotations unless that is the point, and carry no identifiers or telemetry. `deny.toml` bans the HTTP/TLS crates (and `tokio`'s `net` feature) with the ADR as reason; README section «What Tiza reads and writes»; a paragraph for agents in the agent guide; a bullet in AGENTS.md.
- Typos in `:` commands never close the app or leave the terminal broken (t-115). Export sizes are bounded (`width` 20..=400 in `:export`, `tiza render --width`, `render.text {width}` and `export_image`; `--scale` 0.25..=8, font size 4..=96; a PNG over 16384 px per side or 100 MP is refused naming the limit) — `:export x.png width=99999` used to abort the process with an allocation failure and leave the terminal in raw mode. A panic anywhere in the TUI restores the terminal (alternate screen, cursor, raw mode, mouse, bracketed paste) and prints one `tiza crashed: … Your work is in FILE.tiza … issues` line. Out-of-range numbers are rejected or normalised with a notice (`:focus 0`, `:focus 2-99`, `:box -1-3`, `:box 0-0`, `:until ID N` below the spotlight's step, `:step ID N` past `last + 1`); `L:text` whose text is not on line L is an error that says where it is (`«S» not on L3; found on L2 — use 2:S`), a line that does not exist is an error in `:arrow`, `:mark` and `:hl` alike, and the typo shapes `:box 3 - 5`, `:hl 3 s`, `:hl s`, `:mark KIND s` get the usage line instead of an annotation; `:set ID =`, `:style NAME glyph=`, `:lang A B C` and `@bogus` in `:callout` are errors; unknown commands suggest the nearest one (`unknown command: bx — did you mean :box?`). `qa/README.md` carries the checklist for future command cards.
- `--no-save` and `:autosave on|off` (t-110): annotate an example or a demo without the sidecar being rewritten; the bar shows `no-save` / `unsaved (:w)`, `:q` refuses with unsaved changes (`:w`, `:w PATH`, `:q!`), `:autosave on` writes what is pending, `status` carries `autosave`. A sidecar that cannot be written is the same state as `:autosave off` (one rule for `--no-save`, `:autosave off`, a foreign `scene put` and read-only): one notice on the first failed autosave (`read-only: could not save FILE — :w PATH to save elsewhere`), then the message line shows each command's own confirmation and the bar keeps `read-only • unsaved (:w)`; `:q` refuses, `:q!` discards; when the file is writable again the next autosave says `saved to FILE` once and the indicator goes. A sidecar made read-only (`chmod a-w`) is honoured as such: the atomic replace used to rename over it. `examples/README.md` recommends `--no-save`.

### Removed
- The brand serif left the binary (t-134, [ADR 0006](docs/adr/0006-exportacion-svg-png.md) amendment): the four *Tiza Serif* faces are no longer embedded, and `SvgOptions.brand_font`, the prose-run path (natural-width runs, letter-spacing, class `p`) and the `export_image` `brand_font` parameter are gone. Every export (SVG, PNG, GIF, video) is set in JetBrains Mono — the four faces complete — as the default already was: PNG/GIF bytes are unchanged and the default SVG only loses the four serif `@font-face` blocks (step 7 of `examples/ownership.rs.tiza`: 2,135,745 → 1,677,197 bytes). The release binary shrinks by 345,520 bytes (14,341,856 → 13,996,336; gzip −203,272). `--brand-font` and the hidden `--mono-labels` are still accepted for one prerelease as no-ops that print one line on stderr; an MCP client that still sends `brand_font` is ignored. The Libron subset and its OFL license moved to [`docs/brand/fonts/`](docs/brand/fonts/README.md), outside every crate, as brand material for the wordmark and thumbnails (t-069).

### Fixed
- Redaction through moves (t-140, found in the QA of t-117): a `code.patch` that rewrote a redacted line left the mask in its old columns on the new text, so part or all of the value showed (a longer value, a renamed key, a line split in two, a typed move), and `scene.get` / `move.list` returned the moves' content unmasked. Moves now follow the fail-closed rule of a reload: the mask follows the value when the text around it is intact, otherwise widens to the rest of the line from where its text no longer matches, or to every new line of a patch that changes the line count, and is dropped only when its line is deleted with nothing in its place; every frame of a typed move is masked (no `keep` tail on a half-typed value) and a copy of a masked value that a move writes elsewhere is masked too. A redact is pinned to the earliest code that holds its line (its `step` becomes 0 for the file's own lines), so a move added later never moves its columns and going back restores it exactly. A widened or dropped redact is announced when the presenter reaches the step, shows `WIDENED` in `:list`/`scene.list` and `"widened": true` in `scene.get` at that step, and `render` warns once on stderr. Move content is masked in `scene.get`, `move.list`, `list_moves` and `tiza://scene` (the `.tiza` keeps it as written), and `move.add` refuses content that repeats a masked value where no mask covers it, without echoing it. Text targets of later moves are matched with the masks of their point drawn, so a `find` cannot probe a value a move carried along. In a document written by hand, by an agent or before this fix, a redact whose step has a move that rewrites its line could refer to either code: both readings are masked.
- Redaction after a rotated secret (t-117 rework): saving a new value under a masked key (`STRIPE_KEY=sk_live_…` rotated) in follow mode, or pasting it, dropped the redact and showed the new value on screen and in `code.get`. A redact now re-anchors by the text around it, never by the text under it: the text before it (and, for a mask that stops mid-line, the text after it, with other masks on the line as wildcards) locates the new value, which stays masked whatever its length, with `keep=N` showing the new tail. It is dropped, with the loud notice (`redact aN dropped: the line changed — check the screen before recording`), when the text before it is gone, when the text around a mid-line mask (a selection) changed, or when the value is emptied; a redact never falls back to its old columns, which could uncover part of a longer value. `:embed` while following turns follow off (it used to keep reloading the frozen copy and report every redact as dropped).
- Redaction fails closed (t-117 rework 2): a redact that a reload or a paste could not re-anchor used to be dropped, which showed the new value (a selection mid-line whose `"user"` key next to it was renamed, a renamed key under `:redact auto`). Now, while its line is still there, the mask widens to the rest of that line from its old column (from where the line first differs when the text before it changed, the whole line when the column is gone); when the line cannot be told apart (an edit that turned it into several lines) every new line of that edit is masked whole. It is reported loudly (`redact aN could not follow its text: masking the rest of L4 — fix it before recording`), keeps no `keep` tail, and is marked `"widened": true` in the document (`scene.get`, the `.tiza`, the schema) and `WIDENED` in `:list` / `scene.list` until the presenter marks the value again (a new redact over it replaces it). Only a redact whose line was deleted with nothing in its place, or left blank, is dropped, with the old notice. This replaces the previous rule that dropped a redact whose text around it changed or whose value was emptied.
- Box title at the top of the screen (t-114): when the cursor landed on the first line of a box the TUI scrolled that line to the first row and left the box's title row (a virtual row above it) off-screen, so the box showed no top border; the viewport now keeps the title rows of the boxes that open on the cursor line, and the rows under it (emphasis, labels, bottom borders) when they fit. `render`, presentation mode and `FILE:A-B` ranges already reserved the row; `qa/fixtures/t-114/top.tiza` (a box at line 1) covers them.
- Emphasis glyphs softened after the owner's review (t-096): the underline row uses the thin overline `‾` instead of the one-eighth block `▔`, and the underline, the brackets and the struck text are drawn at 75 % of the annotation colour, blended toward the background (55 % read too soft on the second review); the struck text, being code, never drops under the 4.5:1 code contrast (at 75 % the softened red alone measured 4.45:1 after compression) (the span's own text keeps the full colour for underline and brackets), in the TUI and in SVG/PNG alike; the t-072 gate still passes.
- VHS tapes after the owner's `vhs` run (t-051): `Output` is quoted (an absolute path or one with spaces parses in VHS 0.12); the window is sized for the real glyph advance (`cols × 12 + 2 × padding` wide, `(rows + 2) × 24 + 2 × padding` high), so the TUI keeps its margin layout and the last step is not cut at the bottom; the window takes the document theme's background and foreground instead of a VHS preset, so no lighter frame surrounds the TUI; the last step holds twice the interval before the tape ends; `render` prints one hint line on how to play the written `.tape` or `.cast`.
- Supervised mode in presentation mode (t-045): a proposal that arrives while presenting now shows a chip `⏸ N to review` bottom-left (there was no sign at all), and the proposals list pops by itself when leaving presentation mode with items pending; `:` from the list hides it and opens the command line, so Enter ends the command instead of accepting the first proposal.
- `scene put` after the owner's QA (t-039): `u` after a put (or a patch) restores the previous step too, not just the content; `tiza scene put FILE` accepts the `scene get` envelope (`{document, step, …}`), so get → put is a no-op from the CLI, and refuses a file that is neither a document nor an envelope unless `--as-code` is given (a stray JSON file no longer lands on screen as 300 lines of JSON); a put of a document from another source turns autosave off, so an agent can never overwrite the presenter's open file by putting the wrong document (`:w` saves it over on purpose, `:w PATH` elsewhere, `:autosave on` resumes).
- docs/zed.md, after the run in a real Zed (t-012): the selection task is `printf '%s' "$ZED_SELECTED_TEXT" | tiza --lang "$ZED_FILE"` — Zed parses every `$ZED_…` itself and a shell expansion like `${ZED_FILE##*.}` makes it reject the whole tasks file as «unknown variables» (no Tiza task shows); a note that Rust buffers only resolve `$ZED_FILE`/`$ZED_ROW` inside a Cargo workspace (a loose `.rs` hides every task with no error); and a Gotchas list (picker is `task: spawn`, stale history entries after editing tasks.json, `allow_concurrent_runs` does not stop a second spawn and the second instance has its API disabled, selection numbering starts at 1).
- Follow mode, after the owner's second QA round (t-011): a hunk that replaces N lines by N lines (a parameter renamed on the signature line and on the line that uses it) pairs its lines one to one in place like a single edited line, so a mark on `push` and a box around the function survive the rename instead of being dropped as ambiguous; the reflow search only applies when the counts differ. `u` / `U` now say what they undid or redid (`undone: reload #54`, `undone: note a3`, `undone: 3 annotations cleared`, `undone: move #2 added`…), so a harmless reload that pushed no undo step does not leave you guessing what `u` just reverted; a failed add/update/delete no longer leaves a stray redo entry.
- Moves, after the owner's QA (t-098): a paste at step 0 re-applies the moves on the pasted text and re-anchors every annotation on the code at its own step, so annotations that live on code a later move types in are no longer dropped (pasting the identical step-0 code of `examples/ownership-moves.rs.tiza` kept 6 of 8); the generated `.tape` holds a typed step for the typing time plus 500 ms instead of a fixed interval, so the next `n` no longer lands mid-typing and loses a step; `render --step N` past the last step warns on stderr instead of silently showing the last one; a `move.add` rejected because a later move stops applying names that move and its step also for line-range errors; a `rebind` entry with none of `at`, `from`/`to`, `from_line`/`to_line` (for example the `{"find": …}` spelling without `at`) or with an unknown key is a load-time error naming the move and the id instead of being ignored.
- Where a horizontal arrow stub crosses another arrow's vertical rail, the stub now breaks for one cell and the rail shows through, so the arrow reads as passing *under* the rail (Luis's pick over junction glyphs, t-091); rails are drawn after every stub and own their cells. Crossings with a box border keep the junction glyph in the border's color whatever the drawing order (`Canvas::put_line`). `ping` over the socket answers the plain string `"pong"` (the `{type, protocol}` object was redundant: `status` carries `protocol`).
- Follow mode on macOS (t-103): FSEvents reports canonical paths (`/private/var/…`) while `$TMPDIR` is `/var/…`, so no save ever matched the followed file and the t-011 tests timed out on the macOS runner. Event paths and the watched directory are now compared with symlinks resolved on both sides; a unit test reproduces it with a symlinked directory on any OS. CI runs `cargo test --no-fail-fast`, annotates the failing test names and panics, prints the `failures:` block and uploads the log, so the next red run names its test without downloading anything.
- Found by the fuzzer (t-074): a document saved with `"code": []` panicked in the layout (it now loads as one empty line, like `from_code`), and annotations whose lines are outside the code (a file that shrank) crashed the arrow lanes; they are now skipped by the layout (the notice on open, from t-047, still names them).
- Dark theme legibility: syntax colors that fall under 4.5:1 against the background (comments, mostly) are pushed toward the text color until they pass WCAG AA, so they survive video compression; the gutter already did. `theme::contrast` / `Theme::legible`.
- Small polish from the QA rounds: malformed numeric ranges (`12-`, `-5`, `1-2-3`) are errors instead of a silent single line; annotations outside the code are reported when a document opens; `:wq` stays when the write fails; `:step N` with N one past the last step opens an empty step (beyond that it is an error that says which step would); `↑` in the command line stops at the oldest entry; `:` + Tab lists the commands (truncated with `…`); the status bar shortens its hints in tiers (`:cmd ?help n/p steps q quit` → `?help q quit` → `?help`) instead of hiding them, and names the document instead of `(stdin)` for embedded code.
- Margin labels no longer drift next to the wrong line when an earlier label wraps: a label keeps its own row and continues only through rows no other label owns, clipping with `…` otherwise (long text belongs in a callout).
- Labels, notes and titles are single-line (control characters become spaces); loading a document clamps `step` to its last step and rejects duplicate ids; the line-number gutter reserves a column for the cursor/selection marker so three-digit numbers keep every digit; `--padding` is taken into account by the viewport warning; `theme.set` with a non-string value is rejected; help and list overlays no longer panic on terminals under 8×4.
- `:pad 0 0` really removes the padding (it used to fall back to the default); `:pad default` restores it. SVG/PNG size no longer gains a pixel from float rounding (50 cols → 480 px).
- A callout placed below is drawn inside a box only when the box contains its whole range; a callout wider than the box (e.g. one that sums up several functions) now goes after the box's bottom border, without the box's rail or background. The ownership example's `move` mark on line 3 points at the argument `s` instead of the `s` in `takes`.

### Added
- Moves (t-098, ADR 0007): a `.codedraw` may carry `moves`, `code.patch` entries that insert, replace or delete whole lines when the presenter reaches `at_step` and are reverted when going back; the document is recomputed from the step-0 code every time (no diff of diffs). Targets are matched on the code as shown at that step and must match exactly once (`after`/`before`/`position` for inserts, `find`/`find_start`+`find_end`/`position` for replace and delete); load-time and `move.add` errors name the move. `typing: line|char` types the content in place in the TUI (`speed_ms` per unit; blank placeholder lines keep the layout steady; any key finishes it; the step's annotations appear when it ends). Annotations are authored against the code at their own step (`annotation.add` validates on that step's code) and shifted deterministically through later patches by the patch's own line map — never by a text search; one that loses every line is hidden and listed as `(unanchored)` in `scene.list`/`:list`, unless the move's `rebind` says where it goes. A `replace` keeps line-level annotations (note, box, callout, spotlight) on the same-offset line but unanchors column anchors (highlight, mark, arrow ends) unless `rebind`; `occurrence: N` (1-based over the whole code at that step; `end_occurrence` for `find_end`) picks a match on every text target and on `rebind` finds, which are validated when the move is added. Socket `move.add`/`move.delete`/`move.list`, MCP `add_move`/`delete_move`/`list_moves`, `scene.get` carries `moves` with the step-0 code embedded; the saved file and `:embed` always keep the step-0 code; `render --step N`, `.cast` and `.tape` apply the moves instantly; paste and follow are refused while a move is applied. Example `examples/ownership-moves.rs.codedraw`; undo covers moves and typing.
- Range anchors by two text markers (t-097): boxes, callouts and spotlights accept `find_start`/`find_end` on the socket and in the MCP tools, and `:box @'// begin'..@'// end' label` (also `:callout`, `:spot`) in the TUI; resolved at creation (first start anywhere, first end at or after it, same line allowed) and stored as lines plus `markers: {start, end}` on the annotation (shown in `scene.list`, dropped when the annotation is moved by lines). Missing markers fail with `text_not_found` naming them; an end that only appears before the start is `invalid_argument`.
- Mouse support, opt-in (t-033): `--mouse` / `:mouse on|off`. Click moves the cursor to the line and grapheme (tabs and wide glyphs by display width; virtual rows snap to the code line above), drag selects a span or a line range and leaves the selection open for the usual actions, the wheel scrolls three rows; ignored while an overlay or the command line is open, and in presentation mode (`P`), where the cursor and the selection are hidden — the capture stays on, so back in normal mode the mouse works again. Off by default so the terminal keeps its native selection (README explains Shift/Option-drag, Zed's Cmd+click and tmux).
- Legibility check (t-072): `scripts/legibility.py DOC --step N --theme dark|light` renders, scales to 1920×1080, round-trips through H.264 at a YouTube-like bitrate and measures the contrast each text color keeps (stroke cores vs background); exit 1 under 4.5:1. The ownership example passes in both themes (worst ≈ 4.9 dark, ≈ 5.0 light). CI job `legibility` runs it and uploads the report; `qa/tests/t-072.rs` also checks every theme role before compression.
- Brand typography in exports (t-068): notes, labels, mark legends and under-line labels can be set in *Tiza Serif* (first shipped as *CodeDraw Serif*, renamed with the project), a Latin subset of Libron (OFL, renamed per the license) embedded in the binary and in the SVG (four faces, ~340 KB); code, numbers, boxes and titles stay in JetBrains Mono. New `CellStyle.prose` flag (ignored by the terminal). After the owner's review the serif became opt-in (see Changed), and t-134 later took it out of the binary (see Removed); it lives on as brand material in [`docs/brand/fonts/`](docs/brand/fonts/README.md).
- Recordings from the steps (t-051): `codedraw render FILE --out x.cast` writes an asciicast v3 (header with the document title, one marker + one frame per step from step 0, `--interval` seconds apart, theme background, CRLF, no scrolling) and `--out x.tape` a VHS tape that drives the real TUI through the steps (`vhs x.tape` → `x.gif`). `--format cast|tape`, `--skip-zero`, `--title`; the live instance can be recorded too.
- Supervised mode (t-045): `:supervise on|off` / socket `supervise.set`, `supervise.status`. Mutating requests from agents are parked as proposals; the review overlay (`:review`, `y`/`n`/`a`/`d`, Esc) and the `⏸ N to review` chip show them; the agent's call returns the normal result on `y`, error `rejected` on `n`, on `:supervise off` or after 60 s undecided. Read-only methods never wait; `status` carries `supervised` and `pending`. The socket client read timeout grew to 75 s to outlive a proposal.
- MCP resources (t-044): `codedraw://scene` (JSON), `codedraw://code` (numbered text), `codedraw://render` (current frame) and `codedraw://render.md` (fenced block with the file name and step), listed with descriptions and MIME types; unknown URIs answer *resource not found* with the list.
- `codedraw scene put FILE|-` replaces the live document atomically (code resolved relative to the file and embedded on the wire; one undo step) and `codedraw scene patch JSON|-|@file` applies partial changes: `step`, `theme`, `padding`, `title`, `styles` (merged by name) and `annotations` merged by id in document format (same id replaces, new id adds, `{"id", "deleted": true}` removes); unknown keys are rejected and nothing is applied when one entry is invalid. Socket methods `scene.put` / `scene.patch` (t-039). `:title` and `:pad` are now undoable with `u`.
- Input fuzzing (t-074): proptest suites over the `.codedraw` parser (random bytes, random JSON, mutations of a valid document), the `:` commands (every command with random arguments, raw lines) and the socket (garbage NDJSON, random methods/params); `codedraw --smoke` draws one frame, polls the input once and exits, and CI runs it under `script` with stdin piped on Linux and macOS to prove the `/dev/tty` path.
- Build identity (t-082): `codedraw --version` prints the git commit (`0.0.1 (abc1234def)`, `-dirty` for uncommitted changes); `status` carries `build`, and the MCP `status` tool adds `bridge {version, build, binary_rebuilt, instance_build, hint}` so an agent can tell when the binary was rebuilt under a running server and ask for a reconnect. README and agent guide explain why a reconnect (Claude Code `/mcp`) is needed after `cargo build` and why `tools/list_changed` cannot replace it.
- Text exports (t-049): `codedraw render --out x.md` writes a fenced ```` ```text ```` block (document title above) for READMEs, issues and chats, next to `.txt` (no trailing spaces or blank rows) and `.ansi` (24-bit, reset per line); `:export [file] [step=N] [width=N] [theme=…]` in the TUI writes `.txt`, `.ansi`, `.md`, `.svg` or `.png` (default `<doc>-stepN.txt`); the MCP `export_image` tool accepts the three text formats too.
- Language detection (t-013): extension when a grammar exists, then well-known file names (`Makefile`, `Dockerfile`, `Cargo.lock`, `Justfile`, `.bashrc`, `.gitignore`…), then a `#!` line (`env` flags and version suffixes understood), then a Vim/Emacs modeline in the first or last five lines. Piped and pasted code without a language uses the content rules instead of plain text. `:lang` shows the language, `:lang <id>` overrides it (`rust`/`typescript`/`ruby`… normalized), `:lang auto` re-detects and reports the source, and an id without a grammar is accepted with a warning; `--lang` also applies to `codedraw render file`.
- Highlight and mark emphases (t-096): `emphasis` = `fill` (tint, default), `underline` (a virtual row with ▔ under the span), `brackets` (⌈ ⌉ beside the span; a glued side falls back to ⌊ ⌋ on the row below so code is never covered) or `strike` (combining stroke per grapheme, also in SVG/PNG). `:hl … emphasis=…` (`style=` as a synonym on `:hl`), `:mark … emphasis=…`, `:set ID emphasis=…`, socket field on `annotation.add/update`, MCP `highlight` / `add_mark` / `update_annotation`. Several underlined spans on one line share one row.
- Follow mode (`--follow`, `:follow on|off`): the TUI watches the source file's folder (tmp + rename saves included) and reloads the code ~120 ms after the last write, re-anchoring annotations by text like a paste (a box or callout keeps its height when one edge line is edited; the ones whose text is gone are dropped and `u` undoes the reload). Re-anchoring (shared with paste) now runs a line diff and matches lines in order, then the same occurrence of the span inside the line: a note on the second `}` or the second `fn new()` stays on its own copy, a deleted copy drops its annotation instead of jumping to another one, and a moved block is followed when its line is unique and within `reanchor::MAX_DISTANCE` (50 lines). From the QA rounds in real Zed: box, callout and spotlight follow one rule — when an edge line leaves with a moved block the range keeps its height from the edge that stayed (never stretching after the one that left, never dropping a spotlight where a box is kept), and a block cut and pasted elsewhere takes its callout with it (the line diff prefers contiguous runs, so a moved block is one deletion plus one insertion); a line replaced in place keeps its note (a span on it still needs its text); a formatter split or join (rustfmt `Self { items: Vec::new() }` ↔ three lines) carries a span to the one new line that holds its text; and a reload that touches no annotation leaves no undo step, so after an editor undo one `u` reaches the reload that dropped something. Status line `⟳ following · last HH:MM:SSZ`; removed file → waiting; empty intermediate writes deferred; identical content, non-UTF-8 and the sidecar autosave never reload. Socket `follow.set` / `follow.status`, MCP `set_follow` (23 tools). New dependency `notify` 8.2.0 (ADR 0004).
- Backward compatibility harness: `fs::MIGRATIONS` (per-schema migrations applied on load), versioned fixtures under `qa/fixtures/compat/` written by v0.0.1, round-trip + render snapshots per fixture, and a test that fails when `SCHEMA_VERSION` is bumped without a fixture and a migration (`qa/tests/t-073.rs`).
- MCP integration tests with a real stdio client (`qa/tests/t-070.rs`): handshake, all 23 tools, explicit error without an instance and reconnection when the TUI starts later, socket error codes in tool errors, parameter validation, two clients interleaving, and every reply validated against `schema/api.schema.json` / `schema/codedraw.schema.json`.
- Render snapshots (insta + ratatui TestBackend) for every annotation kind, both themes, step 0, presentation mode, selections and the small-terminal badge: `qa/tests/t-053.rs`, 32 snapshots (symbols and styles).
- JSON Schema of the `.codedraw` document and of the local API, generated from the types (`codedraw schema document|api`, `api.schema` over the socket), committed under `schema/` and checked by a test; CI validates every example and fixture against it. `-` means stdin for `codedraw -`, `codedraw render -` (code with `--lang`, or a document) and `codedraw api METHOD -`.
- Box and callout border styles: `border` (solid, dashed, dotted, thick, double), `corners` (rounded, sharp) and `fill` (boxes tinted by default, callouts not). `:box … border=double corners=sharp fill=no`, `:callout … border=…`, `:set ID border|corners|fill=…`, socket fields, MCP `add_box` / `add_callout` / `update_annotation`. A callout below the code never grows past the code column.
- README: an animated GIF of the ownership example, generated from the PNG export of each step (`docs/img/ownership.gif`).
- Property tests (proptest) in `codedraw-core`: anchors never panic on arbitrary code, the layout never overflows the width (20..=240 columns, tabs/emoji/CJK/RTL) and documents round-trip through JSON.
- Paste re-anchors annotations by the text they pointed at (same line first, then anywhere); the ones whose text is gone are dropped with a message and `u` restores them. Pasting while typing a `:` command appends to the command; an empty paste is refused.
- Help and list overlays scroll (`j`/`k`, PgUp/PgDn, `g`/`G`) and show how much is left; `:`, `?` and `L` work while a selection is active; `Tab` at step 0 explains that nothing is visible.
- Arrow styles, per annotation like color: `stroke` (solid, dashed, dotted, thick, double), `route` (rounded, sharp) and `heads` at both ends (none, arrow, dot, bar, open; none+none is a plain connector). `:arrow … stroke=dashed heads=dot,bar route=sharp`, new `:set ID key=value…` (also `e` on a selected annotation), socket fields on `annotation.add/update`, MCP `add_arrow` / `update_annotation` with `stroke`, `route`, `head_start`, `head_end`. Crossings now choose the junction from the two strokes (┼ ┿ ╂ ╋ ╪ ╫ ╬). The ownership example draws the shared borrow dashed and the mutable borrow thick.
- Viewport warnings: a ⚠ badge in the status line when the terminal is smaller than 100×30 (saying when labels go under the lines) or when the widest code line is clipped; `status` returns the same texts in `warnings`. Narrow status bars drop the theme/file/cursor segments before cutting the warning.
- `qa/`: one integration-test crate per board ticket (`qa/tests/t-XXX.rs`, fixtures in `qa/fixtures/`), with a headless `Live` instance (real `App` + socket) to drive keys, commands and the API without a terminal.
- SVG and PNG export (`codedraw render FILE --out x.svg|x.png`, `--step`, `--theme`, `--scale`, `--font-size`, `--margin`, `--radius`, `--no-embed-fonts`, `--system-fonts`). Without FILE it exports what the live instance is showing. MCP tool `export_image`. Fonts (JetBrains Mono + a symbols fallback) are embedded in the binary and in the SVG, so the image looks the same everywhere. New crate `codedraw-export`.
- `scene.get` sends the code embedded, so clients in another directory can render the live document.
- `update_annotation` (MCP) and `annotation.update` (socket, `move`) can move an annotation keeping its type, kind, style and label: `at` for highlights/marks/notes, `from`/`to` for arrows, `from_line`/`to_line` for boxes, callouts, spotlights and notes. Fields that do not apply to the type fail with `invalid_argument`; the MCP tool rejects unknown fields instead of ignoring them.
- `callout` annotation: a bordered multi-line paragraph explaining a range of lines, with optional title, `placement` (`margin`, `below`, `auto`) and `width`. `:callout A[-B] [@below|@margin|@auto] [title="…"] text`, `C` on a selection, `annotation.add` with `type: callout`, MCP `add_callout`. In the margin it reserves its rows and the neighbouring labels are drawn beside it instead of being pushed down; below, boxes extend around it. The ownership example closes with one (step 7).
