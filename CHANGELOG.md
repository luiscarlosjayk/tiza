# Changelog

Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Changed
- Render budget (t-054): a frame with 2,000 lines and 200 annotations went from ~220 ms to ~7 ms in release. Syntax highlighting is memoized (`highlight::highlight_cached`, last four results), the status bar reuses the frame's layout instead of computing a second one (`App::viewport_warnings_for`), and canvas cells store their grapheme inline (`canvas::Sym`, no `String` per cell). `qa/tests/t-054.rs` asserts the budget (16 ms release / 250 ms debug).
- All user-facing text (TUI, CLI, MCP, docs, examples) is now in English. Commands, JSON fields and the Spanish color aliases (`azul`, `verde`…) are unchanged; `:theme` keeps accepting `oscuro`/`claro`.

### Fixed
- Where a horizontal arrow stub crosses a vertical rail or box border, the junction cell keeps the rail's color whatever the drawing order (`Canvas::put_line`), so a crossing reads as the stub passing under the rail (t-091).
- Follow mode on macOS (t-103): FSEvents reports canonical paths (`/private/var/…`) while `$TMPDIR` is `/var/…`, so no save ever matched the followed file and the t-011 tests timed out on the macOS runner. Event paths and the watched directory are now compared with symlinks resolved on both sides; a unit test reproduces it with a symlinked directory on any OS. CI runs `cargo test --no-fail-fast`, annotates the failing test names and panics, prints the `failures:` block and uploads the log, so the next red run names its test without downloading anything.
- Found by the fuzzer (t-074): a document saved with `"code": []` panicked in the layout (it now loads as one empty line, like `from_code`), and annotations whose lines are outside the code (a file that shrank) crashed the arrow lanes; they are now skipped by the layout (the notice on open, from t-047, still names them).
- Dark theme legibility: syntax colors that fall under 4.5:1 against the background (comments, mostly) are pushed toward the text color until they pass WCAG AA, so they survive video compression; the gutter already did. `theme::contrast` / `Theme::legible`.
- Small polish from the QA rounds: malformed numeric ranges (`12-`, `-5`, `1-2-3`) are errors instead of a silent single line; annotations outside the code are reported when a document opens; `:wq` stays when the write fails; `:step N` with N one past the last step opens an empty step (beyond that it is an error that says which step would); `↑` in the command line stops at the oldest entry; `:` + Tab lists the commands (truncated with `…`); the status bar shortens its hints in tiers (`:cmd ?help n/p steps q quit` → `?help q quit` → `?help`) instead of hiding them, and names the document instead of `(stdin)` for embedded code.
- Margin labels no longer drift next to the wrong line when an earlier label wraps: a label keeps its own row and continues only through rows no other label owns, clipping with `…` otherwise (long text belongs in a callout).
- Labels, notes and titles are single-line (control characters become spaces); loading a document clamps `step` to its last step and rejects duplicate ids; the line-number gutter reserves a column for the cursor/selection marker so three-digit numbers keep every digit; `--padding` is taken into account by the viewport warning; `theme.set` with a non-string value is rejected; help and list overlays no longer panic on terminals under 8×4.
- `:pad 0 0` really removes the padding (it used to fall back to the default); `:pad default` restores it. SVG/PNG size no longer gains a pixel from float rounding (50 cols → 480 px).
- A callout placed below is drawn inside a box only when the box contains its whole range; a callout wider than the box (e.g. one that sums up several functions) now goes after the box's bottom border, without the box's rail or background. The ownership example's `move` mark on line 3 points at the argument `s` instead of the `s` in `takes`.

### Added
- Moves (t-098, ADR 0007): a `.codedraw` may carry `moves`, `code.patch` entries that insert, replace or delete whole lines when the presenter reaches `at_step` and are reverted when going back; the document is recomputed from the step-0 code every time (no diff of diffs). Targets are matched on the code as shown at that step and must match exactly once (`after`/`before`/`position` for inserts, `find`/`find_start`+`find_end`/`position` for replace and delete); load-time and `move.add` errors name the move. `typing: line|char` types the content in place in the TUI (`speed_ms` per unit; blank placeholder lines keep the layout steady; any key finishes it; the step's annotations appear when it ends). Annotations are authored against the code at their own step (`annotation.add` validates on that step's code) and shifted deterministically through later patches by the patch's own line map — never by a text search; one that loses every line is hidden and listed as `(unanchored)` in `scene.list`/`:list`, unless the move's `rebind` says where it goes. Socket `move.add`/`move.delete`/`move.list`, MCP `add_move`/`delete_move`/`list_moves`, `scene.get` carries `moves` with the step-0 code embedded; the saved file and `:embed` always keep the step-0 code; `render --step N`, `.cast` and `.tape` apply the moves instantly; paste and follow are refused while a move is applied. Example `examples/ownership-moves.rs.codedraw`; undo covers moves and typing.
- Range anchors by two text markers (t-097): boxes, callouts and spotlights accept `find_start`/`find_end` on the socket and in the MCP tools, and `:box @'// begin'..@'// end' label` (also `:callout`, `:spot`) in the TUI; resolved at creation (first start anywhere, first end at or after it, same line allowed) and stored as lines plus `markers: {start, end}` on the annotation (shown in `scene.list`, dropped when the annotation is moved by lines). Missing markers fail with `text_not_found` naming them; an end that only appears before the start is `invalid_argument`.
- Mouse support, opt-in (t-033): `--mouse` / `:mouse on|off`. Click moves the cursor to the line and grapheme (tabs and wide glyphs by display width; virtual rows snap to the code line above), drag selects a span or a line range and leaves the selection open for the usual actions, the wheel scrolls three rows; ignored while an overlay or the command line is open. Off by default so the terminal keeps its native selection (README explains Shift/Option-drag, Zed's Cmd+click and tmux).
- Legibility check (t-072): `scripts/legibility.py DOC --step N --theme dark|light` renders, scales to 1920×1080, round-trips through H.264 at a YouTube-like bitrate and measures the contrast each text color keeps (stroke cores vs background); exit 1 under 4.5:1. The ownership example passes in both themes (worst ≈ 4.9 dark, ≈ 5.0 light). CI job `legibility` runs it and uploads the report; `qa/tests/t-072.rs` also checks every theme role before compression.
- Brand typography in exports (t-068): notes, labels, mark legends and under-line labels are set in *CodeDraw Serif*, a Latin subset of Libron (OFL, renamed per the license) embedded in the binary and in the SVG (four faces, ~340 KB); code, numbers, boxes and titles stay in JetBrains Mono. `--mono-labels` keeps everything monospace. New `CellStyle.prose` flag (ignored by the terminal).
- Recordings from the steps (t-051): `codedraw render FILE --out x.cast` writes an asciicast v3 (header with the document title, one marker + one frame per step from step 0, `--interval` seconds apart, theme background, CRLF, no scrolling) and `--out x.tape` a VHS tape that drives the real TUI through the steps (`vhs x.tape` → `x.gif`). `--format cast|tape`, `--skip-zero`, `--title`; the live instance can be recorded too.
- Supervised mode (t-045): `:supervise on|off` / socket `supervise.set`, `supervise.status`. Mutating requests from agents are parked as proposals; the review overlay (`:review`, `y`/`n`/`a`/`d`, Esc) and the `⏸ N to review` chip show them; the agent's call returns the normal result on `y`, error `rejected` on `n`, on `:supervise off` or after 60 s undecided. Read-only methods never wait; `status` carries `supervised` and `pending`. The socket client read timeout grew to 75 s to outlive a proposal.
- MCP resources (t-044): `codedraw://scene` (JSON), `codedraw://code` (numbered text), `codedraw://render` (current frame) and `codedraw://render.md` (fenced block with the file name and step), listed with descriptions and MIME types; unknown URIs answer *resource not found* with the list.
- `codedraw scene put FILE|-` replaces the live document atomically (code resolved relative to the file and embedded on the wire; one undo step) and `codedraw scene patch JSON|-|@file` applies partial changes: `step`, `theme`, `padding`, `title`, `styles` (merged by name) and `annotations` merged by id in document format (same id replaces, new id adds, `{"id", "deleted": true}` removes); unknown keys are rejected and nothing is applied when one entry is invalid. Socket methods `scene.put` / `scene.patch` (t-039). `:title` and `:pad` are now undoable with `u`.
- Input fuzzing (t-074): proptest suites over the `.codedraw` parser (random bytes, random JSON, mutations of a valid document), the `:` commands (every command with random arguments, raw lines) and the socket (garbage NDJSON, random methods/params); `codedraw --smoke` draws one frame, polls the input once and exits, and CI runs it under `script` with stdin piped on Linux and macOS to prove the `/dev/tty` path.
- Build identity (t-082): `codedraw --version` prints the git commit (`0.0.1 (abc1234def)`, `-dirty` for uncommitted changes); `status` carries `build`, and the MCP `status` tool adds `bridge {version, build, binary_rebuilt, instance_build, hint}` so an agent can tell when the binary was rebuilt under a running server and ask for a reconnect. README and agent guide explain why a reconnect (Claude Code `/mcp`) is needed after `cargo build` and why `tools/list_changed` cannot replace it.
- Text exports (t-049): `codedraw render --out x.md` writes a fenced ```` ```text ```` block (document title above) for READMEs, issues and chats, next to `.txt` (no trailing spaces or blank rows) and `.ansi` (24-bit, reset per line); `:export [file] [step=N] [width=N] [theme=…]` in the TUI writes `.txt`, `.ansi`, `.md`, `.svg` or `.png` (default `<doc>-stepN.txt`); the MCP `export_image` tool accepts the three text formats too.
- Language detection (t-013): extension when a grammar exists, then well-known file names (`Makefile`, `Dockerfile`, `Cargo.lock`, `Justfile`, `.bashrc`, `.gitignore`…), then a `#!` line (`env` flags and version suffixes understood), then a Vim/Emacs modeline in the first or last five lines. Piped and pasted code without a language uses the content rules instead of plain text. `:lang` shows the language, `:lang <id>` overrides it (`rust`/`typescript`/`ruby`… normalized), `:lang auto` re-detects and reports the source, and an id without a grammar is accepted with a warning; `--lang` also applies to `codedraw render file`.
- Highlight and mark emphases (t-096): `emphasis` = `fill` (tint, default), `underline` (a virtual row with ▔ under the span), `brackets` (⌈ ⌉ beside the span; a glued side falls back to ⌊ ⌋ on the row below so code is never covered) or `strike` (combining stroke per grapheme, also in SVG/PNG). `:hl … emphasis=…` (`style=` as a synonym on `:hl`), `:mark … emphasis=…`, `:set ID emphasis=…`, socket field on `annotation.add/update`, MCP `highlight` / `add_mark` / `update_annotation`. Several underlined spans on one line share one row.
- Follow mode (`--follow`, `:follow on|off`): the TUI watches the source file's folder (tmp + rename saves included) and reloads the code ~120 ms after the last write, re-anchoring annotations by text like a paste (a box or callout keeps its height when one edge line is edited; the ones whose text is gone are dropped and `u` undoes the reload). Re-anchoring (shared with paste) now runs a line diff and matches lines in order, then the same occurrence of the span inside the line: a note on the second `}` or the second `fn new()` stays on its own copy, a deleted copy drops its annotation instead of jumping to another one, and a moved block is followed when its line is unique and within `reanchor::MAX_DISTANCE` (50 lines). Status line `⟳ following · last HH:MM:SSZ`; removed file → waiting; empty intermediate writes deferred; identical content, non-UTF-8 and the sidecar autosave never reload. Socket `follow.set` / `follow.status`, MCP `set_follow` (23 tools). New dependency `notify` 8.2.0 (ADR 0004).
- Backward compatibility harness: `fs::MIGRATIONS` (per-schema migrations applied on load), versioned fixtures under `qa/fixtures/compat/` written by v0.0.1, round-trip + render snapshots per fixture, and a test that fails when `SCHEMA_VERSION` is bumped without a fixture and a migration (`qa/tests/t-073.rs`).
- MCP integration tests with a real stdio client (`qa/tests/t-070.rs`): handshake, all 23 tools, explicit error without an instance and reconnection when the TUI starts later, socket error codes in tool errors, parameter validation, two clients interleaving, and every reply validated against `schema/api.schema.json` / `schema/codedraw.schema.json`.
- Render snapshots (insta + ratatui TestBackend) for every annotation kind, both themes, step 0, presentation mode, selections and the small-terminal badge: `qa/tests/t-053.rs`, 32 snapshots (symbols and styles).
- JSON Schema of the `.codedraw` document and of the local API, generated from the types (`codedraw schema document|api`, `api.schema` over the socket), committed under `schema/` and checked by a test; CI validates every example and fixture against it. `-` means stdin for `codedraw -`, `codedraw render -` (code with `--lang`, or a document) and `codedraw api METHOD -`.
- Box and callout border styles: `border` (solid, dashed, dotted, thick, double), `corners` (rounded, sharp) and `fill` (boxes tinted by default, callouts not). `:box … border=double corners=sharp fill=no`, `:callout … border=…`, `:set ID border|corners|fill=…`, socket fields, MCP `add_box` / `add_callout` / `update_annotation`. A callout below the code never grows past the code column.
- README: an animated GIF of the ownership example, generated from the PNG export of each step (`docs/img/ownership.gif`).
- Property tests (proptest) in `codedraw-core`: anchors never panic on arbitrary code, the layout never overflows the width (20..=240 columns, tabs/emoji/CJK/RTL) and documents round-trip through JSON.
- Paste re-anchors annotations by the text they pointed at (same line first, then anywhere); the ones whose text is gone are dropped with a message and `u` restores them. Pasting while typing a `:` command appends to the command; an empty paste is refused.
- Help and list overlays scroll (`j`/`k`, PgUp/PgDn, `g`/`G`) and show how much is left; `:`, `?` and `L` work while a selection is active; `Tab` at step 0 explains that nothing is visible.
- Arrow styles, per annotation like color: `stroke` (solid, dashed, dotted, thick, double), `route` (rounded, sharp) and `heads` at both ends (none, arrow, dot, bar, open; none+none is a plain connector). `:arrow … stroke=dashed heads=dot,bar route=sharp`, new `:set ID key=value…` (also `e` on a selected annotation), socket fields on `annotation.add/update`, MCP `add_arrow` / `update_annotation` with `stroke`, `route`, `head_start`, `head_end`. Crossings now choose the junction from the two strokes (┼ ┿ ╂ ╋ ╪ ╫ ╬). The ownership example draws the shared borrow dashed and the mutable borrow thick.
- Viewport warnings: a ⚠ badge in the status line when the terminal is smaller than 100×30 (saying when labels go under the lines) or when the widest code line is clipped; `status` returns the same texts in `warnings`. Narrow status bars drop the theme/file/cursor segments before cutting the warning.
- `qa/`: one integration-test crate per board ticket (`qa/tests/t-XXX.rs`, fixtures in `qa/fixtures/`), with a headless `Live` instance (real `App` + socket) to drive keys, commands and the API without a terminal.
- SVG and PNG export (`codedraw render FILE --out x.svg|x.png`, `--step`, `--theme`, `--scale`, `--font-size`, `--margin`, `--radius`, `--no-embed-fonts`, `--system-fonts`). Without FILE it exports what the live instance is showing. MCP tool `export_image`. Fonts (JetBrains Mono + a symbols fallback) are embedded in the binary and in the SVG, so the image looks the same everywhere. New crate `codedraw-export`.
- `scene.get` sends the code embedded, so clients in another directory can render the live document.
- `update_annotation` (MCP) and `annotation.update` (socket, `move`) can move an annotation keeping its type, kind, style and label: `at` for highlights/marks/notes, `from`/`to` for arrows, `from_line`/`to_line` for boxes, callouts, spotlights and notes. Fields that do not apply to the type fail with `invalid_argument`; the MCP tool rejects unknown fields instead of ignoring them.
- `callout` annotation: a bordered multi-line paragraph explaining a range of lines, with optional title, `placement` (`margin`, `below`, `auto`) and `width`. `:callout A[-B] [@below|@margin|@auto] [title="…"] text`, `C` on a selection, `annotation.add` with `type: callout`, MCP `add_callout`. In the margin it reserves its rows and the neighbouring labels are drawn beside it instead of being pushed down; below, boxes extend around it. The ownership example closes with one (step 7).
- Default padding of one column at the left and right edges when the document sets none (`:pad 0 0` removes it, `:pad default` restores the default).
- `Tab`/`Shift-Tab` select an annotation in reading order; on it, `Enter` edits the label, `x` deletes, `c` changes the color, `+`/`-` move it between steps.
- Command line: `Tab` completes commands, mark kinds, annotation ids and themes; `↑`/`↓` browse the history.
- Padding around the drawing: `--padding V[,H]` when opening and `:pad V [H]` live; stored in the document (`padding: [v, h]`).
- Keyboard selection, vim style: column cursor with `h`/`l`/`w`/`b`/`e`/`0`/`$`, `v`/`V`/`i` selections, and selection actions `h` (highlight), `m` (mark, command line pre-filled), `n` (note), `b` (box), `a` (arrow in two selections), `s` (spotlight). Explicit anchors `L@S..E` and `L@C`. The annotation list moves to `L`.
- Generic, language-agnostic mark kinds (info, warn, error, ok, question, important, read, write, move, new, drop, scope, flow, todo) replacing the Rust-only set; Rust names remain as aliases. Custom styles in two modes: inline per annotation (`style: {glyph, legend, color}`, emoji allowed) and reusable document `styles` (`:style NAME …`, MCP `define_style`, `list_kinds`). `:mark 🔥 L:text legend` creates a one-off mark.
- `spotlight` annotation: a step that directs attention by dimming the code outside a range and/or the annotations outside a group (`:spot`, `:until`, `add_spotlight`, `annotation.add` with `type: spotlight`). The ownership example interleaves two.
- `code` as an object `{"file", "lines"}` with absolute paths or paths relative to the `.codedraw`; sidecars reference the source by default. `:embed` and `:link`.
- Step 0 = code only: `p` from step 1, `:step 0`, `--step 0` or `set_step 0` show the code without annotations. The ownership example starts that way.
- Clear annotations at once: `:clear [N|.]`, the `scene.clear` method and the `clear_annotations` MCP tool; reversible with `u`.
- Color per annotation (`color`: palette name or `#rrggbb`) in the model, `:color ID …`, API and MCP. Arrows without a color rotate through a palette so they can be told apart; the ownership example uses one color per value.

## [0.0.1] - 2026-10-16

First working demo.

### Added
- TUI (ratatui + crossterm): code with syntax highlighting (syntect + two-face), line cursor, scrolling, switchable dark/light theme, presentation mode, steps, undo/redo, annotation list and help.
- Annotations anchored to the text: highlights, Rust marks (move, borrow, &mut, drop, lifetime), boxes with virtual rows, arrows along a left lane and on the same line, notes in the margin or below.
- `:` command line (`:mark`, `:arrow`, `:box`, `:hl`, `:note`, `:step`, `:del`, `:label`, `:focus`, `:theme`, `:lang`, `:w`, `:q`…).
- Input: file, file with range `a.rs:12-48`, stdin, paste (bracketed paste).
- `.codedraw` format (JSON, `schema: 1`) with atomic autosave and a sidecar next to the source.
- Local API over a Unix socket (NDJSON, herdr style) and `codedraw scene|api|render` CLI.
- MCP server (`codedraw mcp`) with 16 tools, text anchors (`find`).
- `examples/ownership.rs.codedraw` example (5 steps), agent guide, Zed integration, ADRs 0001–0005.
- CI (fmt, clippy, tests on macOS and Linux, cargo-deny) and releases with binaries from tags.
